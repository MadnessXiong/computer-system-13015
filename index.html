计算机系统概述

先建立全景图

先用一句话理解

把计算机看作一条接力线：程序和数据放在存储器里，CPU按指令取、译、执行，I/O与外部交换；不同抽象层让同一程序从源代码走到机器运行。

记忆钩子

一条线：源代码 → 翻译/链接 → 可执行文件 → 加载 → 取指执行；一个式子：CPU时间＝动态指令数×平均CPI÷频率。

本章怎么学

跟着算一遍 / 想一遍

例：4×10⁸条指令、平均CPI=1.5、主频3GHz。总周期=6×10⁸，CPU时间=0.2秒。这里不把等待I/O的墙钟时间硬塞进CPU时间。

容易混淆

  • “频率更高”不自动等于程序更快：动态指令数和CPI也可能变。
  • CPU时间与墙钟时间统计范围不同，答题先写口径。

合上书自测

  1. 不看书，画出从源程序到程序运行的5个环节。
  2. 说出CPI公式三个量的单位；解释为何墙钟时间不一定等于CPU时间。

1.1

计算机基本工作原理

一句话记住

取指看PC，译码看操作，执行后更新状态。

这样理解：CPU像照菜谱做菜：PC指出下一条菜谱，存储器同时放菜谱和食材。

冯·诺依曼结构的关键不是“有五个部件”这句名单，而是指令与数据都以编码形式存入存储器。CPU内的控制部分依次取指、译码并发出控制信号；运算部分处理操作数，结果可能写回寄存器或存储器。输入输出设备让程序与外部交换。把一次执行看成状态的连续变化，之后学寄存器、cache、中断才有共同的主线。

按教材三级目录逐项核对（2点）
  1. 1.1.1 冯·诺依曼结构基本思想

    程序与数据编码后同存于存储器；CPU按程序计数器所指位置取指。五大部件是结构描述，“存储程序、顺序执行并可转移”解释了工作方式。

  2. 1.1.2 程序和指令的执行过程

    一条指令改变寄存器、存储器或控制流等状态；常按取指、译码、取操作数、执行、写回理解，具体指令未必经过完全相同的动作。

做题步骤 / 表述模板

画一张最小框图：存储器→CPU取指，CPU↔存储器取数/写回，CPU↔I/O交换。遇“指令周期”题先写取指、译码、执行、写回等可能环节，再按题设处理访存或异常；这些环节并非每条指令都用同样时长。

别混淆：时钟周期是时钟节拍，指令周期是一条指令完成所经历的时间；不要机械认为“一条指令＝一个时钟周期”。

合书自测：程序和数据都在存储器中，为什么CPU不会把一段普通数据自动当作指令执行？点击看解析

关键在控制流：CPU按程序计数器指向的地址取指并按指令编码译码。普通数据只有被当作指令地址取来并执行才会变成指令；“都用二进制保存”不等于用途相同。

1.2

程序的开发与运行

一句话记住

编译产目标，链接产可执行，加载进进程。

这样理解：源文件像零件图，目标文件像做好的零件，链接把零件装配，加载才开机。

源程序是人容易写和读的表示；编译与汇编产生机器级目标文件，链接把分散的目标文件与库联系起来，加载则让可执行文件进入运行环境。一个文件可以多次启动，形成不同进程。因此“程序文件”和“运行中的程序”不是同一实体。

按教材三级目录逐项核对（3点）
  1. 1.2.1 程序设计语言和翻译程序

    高级语言需经编译或解释等机制才能在目标机器上运行；汇编器把汇编表示转成机器码。区分“源语言表示”与“机器实际执行的编码”。

  2. 1.2.2 从源程序到可执行文件

    常见C工具链是预处理→编译→汇编→链接；分别产生预处理结果、汇编/目标文件、可执行文件。题目给出具体工具链时以其阶段定义为准。

  3. 1.2.3 可执行文件的启动和执行

    启动涉及操作系统建立运行环境并转入程序入口；可执行文件是磁盘上的程序映像，进程是正在运行的执行实例。

做题步骤 / 表述模板

把题目给出的产物按源代码→预处理→编译→汇编→链接→可执行文件→加载/执行排序。若问函数地址为何改变，先判断是编译生成代码、链接重定位还是运行时加载/动态链接。

别混淆：不能把链接与加载合并成一个步骤，也不能说编译器独自完成所有符号解析。

合书自测：两个C文件分别引用对方定义的函数，哪个阶段使引用与定义最终对应？点击看解析

常规静态链接模型中由链接器进行符号解析并按目标文件信息重定位；编译单个翻译单元时可以先留下待解决的外部引用。动态链接情形还要另说明运行时机制。

1.3

计算机系统的层次结构

一句话记住

源码移植看重编译，二进制运行还看ISA、ABI与系统。

这样理解：ISA像插座规格，微体系结构像插座内部线路；同规格可以有不同速度。

应用程序通常不直接控制晶体管。高级语言、操作系统接口、指令集体系结构（ISA）和硬件实现形成不同观察层：上层只依赖下层公开的行为，下层可以换内部实现。ISA是软件可见的机器接口，微体系结构则是实现同一ISA的具体组织。

按教材三级目录逐项核对（3点）
  1. 1.3.1 计算机系统抽象层的转换

    高级语言经编译落到ISA层，ISA再由硬件实现；每层暴露接口并隐藏内部细节。要辨明转换是编译、系统调用还是硬件执行。

  2. 1.3.2 计算机系统的不同用户

    应用程序员、系统程序员与硬件设计者关心的接口不同；同一故障可从源代码、系统调用、ISA或电路层分别定位。

  3. 1.3.3 计算机系统核心层之间的关联

    源代码的类型与控制流影响机器指令，机器指令又触发存储和I/O；“跨层追踪一条程序”是六章的总线索。

做题步骤 / 表述模板

遇“两个CPU能运行同一个二进制程序吗”，依次检查ISA、ABI、目标文件格式和运行环境；遇“源代码能否移植”，再考虑能否重新编译与适配。先分清源代码级与二进制级兼容。

别混淆：“ISA相同”不保证操作系统、调用约定或文件格式都相同；反之内部cache不同并不必然改变ISA。

合书自测：同一ISA的两台处理器为什么可以有不同的CPI？点击看解析

ISA规定软件可见的指令行为，不规定每条指令内部需要几个周期。流水线、cache、分支预测和实现细节可不同，因而同一程序的平均CPI可不同。

1.4

计算机系统性能评价

一句话记住

先定任务与时间口径，再用IC×CPI÷频率；加速比是旧时间÷新时间。

这样理解：响应时间是“我等多久”，吞吐率是“一小时接待多少人”。

性能是针对任务和指标的比较。响应时间看一项任务多久完成，吞吐率看单位时间完成多少项，CPU时间只计处理器为任务运行的时间。公式CPU时间＝动态指令数IC×平均CPI×时钟周期＝IC×CPI÷频率；这是同一工作量下分析处理器时间的常用模型。

补足关键机制 / 算例

只优化一部分时，不能把局部加速比当整体加速比。例：原时间80%可加速2倍，20%不变，新时间=0.8/2+0.2=0.6倍原时间，整体加速比=1/0.6≈1.67。MIPS=指令数/(执行秒数×10⁶)，不同ISA或程序的指令工作量可能不同，不能只凭MIPS选机器。基准程序比较应说明工作负载、输入、软硬件环境与计时口径；换了任务，排名可能改变。

按教材三级目录逐项核对（3点）
  1. 1.4.1 计算机性能的测试

    先定要比较的工作负载与计时口径：响应时间是单任务耗时，吞吐率是单位时间完成量。墙钟时间可含等待，CPU时间只按处理器运行口径。

  2. 1.4.2 用指令执行速度进行性能评估

    CPU时间=动态指令数×平均CPI÷频率；各指令类CPI须按动态执行次数加权。主频或MIPS单独提高，不保证同一程序的时间缩短。

  3. 1.4.3 用基准程序进行性能评估

    基准程序要固定任务、输入、编译与运行条件；综合成绩还需说明汇总规则。不能把一项基准的排名直接推广到所有应用。

做题步骤 / 表述模板

四步算题：①写清任务和计时范围；②求动态指令总数及各类指令周期之和；③平均CPI＝Σ(ICᵢ×CPIᵢ)/ΣICᵢ；④CPU时间＝总周期/频率，统一Hz与秒。比较优化时用旧时间/新时间求加速比，并检查未优化部分。

别混淆：不要把各类CPI不加权地平均，也不要仅凭GHz或MIPS断言实际程序更快。等待I/O、并行线程与墙钟口径须单列。

合书自测：80%指令CPI为1，20%指令CPI为3，平均CPI是多少？点击看解析

平均CPI＝0.8×1＋0.2×3＝1.4。比例是动态指令比例；若题目给的是程序执行时间比例，就不能直接这样加权。

1.1 自编练习题：指令与数据都存于内存，CPU凭什么知道下一次取哪个位置当指令？

查看分步解析

程序计数器PC给出下一取指位置，控制器按该位置取指并译码；普通数据不会仅因也用二进制存放就自动执行。分支等指令可改变下一次PC。

1.2 自编练习题：甲.c调用乙.c中的函数。甲.c已编译成甲.o却仍留有未解析引用，这是否说明编译失败？

查看分步解析

不一定。分别编译时甲.o可以记录对外部函数的未定义引用；链接阶段再把引用与乙.o或库中的定义对应，并处理重定位。若最终找不到定义，链接才可能报错。

1.3 自编练习题：两台CPU实现同一ISA，同一二进制程序的CPI是否一定相同？

查看分步解析

不一定。ISA规定软件可见行为，不固定内部流水线、cache、分支预测等实现；这些机制可改变同一程序的平均CPI。

1.4 自编练习题：某程序原时间的80%可被加速2倍，其余不变。整体加速比是多少？

查看分步解析

设原时间为1，新时间=0.8/2+0.2=0.6；加速比=1/0.6≈1.67。常错是直接写2，忽视未改进的20%。

数据的表示和运算

先定编码，再算结果

先用一句话理解

同一串0和1可以解释成无符号数、补码、浮点数或字符；“怎么解释”比“怎么计算”先一步。固定宽度会截断；浮点还会对阶和舍入。

记忆钩子

整数题五步：位宽 → 编码 → 运算 → 截断 → 标志。浮点加减四步：对阶 → 尾数运算 → 规格化 → 舍入/溢出检查。

本章怎么学

跟着算一遍 / 想一遍

例：8位7FH+01H=80H。按无符号解释为127+1=128，没有向第9位进位，CF=0；按补码解释为127+1超出最大127，OF=1。

容易混淆

  • CF是无符号进位，OF是有符号溢出；二者不能互换。
  • 原码乘法先算符号异或，再算数值部分；只写十进制乘积会漏掉过程。
  • 浮点打印为0.1不代表二进制存储恰好等于1/10。

合上书自测

  1. 解释同一位型80H为何在8位无符号与补码下数值不同。
  2. 不看答案写出原码一位乘法的符号与部分积步骤。
  3. 说出binary32阶码全1时的两类特殊值。

2.1

数制和编码

一句话记住

写位权；再分清原码、反码、补码与移码的适用场景。

这样理解：进制是写法，机器数编码是解释规则：同一串位可以被不同规则读成不同数。

二进制、十进制、十六进制只是同一数值的不同写法；“编码”进一步规定位串代表什么。位置计数法中每位的权是基数的整数次幂。BCD把每个十进制数字分开编码，不能把整个十进制数直接当二进制整数。

补足关键机制 / 算例

对带符号定点数，原码用最高位表符号、其余位表绝对值；反码负数由对应正数逐位取反；补码负数由对应正数取反加1。n位原码和反码有正零与负零，n位补码只有一个零，且负数范围多一个最小值。移码常用于比较阶码；具体偏置量依格式约定，不能盲目套127。

按教材三级目录逐项核对（3点）
  1. 2.1.1 信息的二进制编码

    位串只是容器，编码规则决定其表示数值、字符或指令；先问“按什么编码解释”，再运算。

  2. 2.1.2 进位记数制

    位置计数法的每位权是基数幂；二进制和十六进制每4位对应一组，转换时先区分数值与BCD数码。

  3. 2.1.3 定点数的编码表示

    原码分符号与数值，反码负数逐位取反，补码负数取反加1；移码另加偏置。做题必须先声明位宽与零的表示方式。

做题步骤 / 表述模板

进制转换先写位权；二进制与十六进制每4位一组。8421 BCD先逐个十进制数码检查是否在0—9，再各用4位表示；十进制10应写成0001 0000，而不是单组1010。

别混淆：0x10是十六进制整数16；BCD的0001 0000代表十进制两个数码“10”，两者位型可同但解释不同。

合书自测：单个8421 BCD数码1010有效吗？十进制10又怎样编码？点击看解析

1010₂对应十进制10，超出单个BCD数码的0—9范围，故无效。十进制10含数码1和0，分组编码为0001 0000。

2.2

整数的表示

一句话记住

无符号看CF；同号相加得异号看有符号OF。

这样理解：位宽像固定长度的表格：算出的高位放不下会被截掉，是否溢出还看按哪种数解释。

n位无符号数范围是0到2ⁿ−1；n位补码范围是−2ⁿ⁻¹到2ⁿ⁻¹−1。补码加减可以按模2ⁿ运算，但“位型结果”与“数学结果是否超范围”是两个问题。最小负数的相反数不能用同宽补码表示。

补足关键机制 / 算例

C语言整数提升和有符号/无符号混合运算可改变比较结果。题目若涉及C表达式，先按题设类型规则确定参与运算的类型；不要把机器补码位型直接等同于C语言有符号溢出的行为。

按教材三级目录逐项核对（3点）
  1. 2.2.1 无符号整数的表示

    n位无符号整数范围0到2ⁿ−1；超宽结果若截成n位，位型按模2ⁿ保留。

  2. 2.2.2 带符号整数的表示

    n位补码范围−2ⁿ⁻¹到2ⁿ⁻¹−1；同一位型按有符号和无符号解释会得到不同数。符号扩展要复制最高符号位。

  3. 2.2.3 C语言中的整数类型

    C整数类型的宽度与转换规则受实现和题设约束；有符号与无符号混合比较时，先确定转换后的共同类型，不凭直觉比较。

做题步骤 / 表述模板

计算顺序：确定位宽与有符号性→必要时符号扩展或零扩展→做n位运算并截断→分别判断CF和OF。无符号加法的CF看最高位进位；有符号加法的OF看同号操作数是否得到异号结果。减法要按题设ISA的借位/进位定义。

别混淆：8位80H按无符号是128，按补码是−128。CF与OF不是同一个标志；两个都为0或都为1也不能靠猜。

2.3

实数的表示

一句话记住

阶码全0看零/非规格化；全1看无穷/NaN；其余按偏置求值。

这样理解：浮点数像“有效数字×10的指数”的二进制版本；指数决定量级，尾数决定精细程度。

浮点数把数量级与有效数字分开保存，换来了大范围，却只能表示有限个离散值。IEEE 754 binary32由1位符号、8位阶码、23位尾数字段组成；普通规格化数有隐含的前导1，有效精度为24位。阶码全0或全1是特殊分类入口。

补足关键机制 / 算例

binary32最小正规格化数是2⁻¹²⁶；最小正非规格化数是2⁻¹⁴⁹。非规格化数的有效数没有隐含前导1，阶指数按1−127计算：尾数最低位为1时，2⁻²³×2⁻¹²⁶=2⁻¹⁴⁹。NaN的阶码全1且尾数非零；无穷尾数为零。

按教材三级目录逐项核对（3点）
  1. 2.3.1 浮点数的表示格式

    浮点数拆为符号、阶码、尾数；规格化扩大有效精度但可表示值仍离散。公式和尾数范围依具体格式。

  2. 2.3.2 IEEE 754浮点数标准

    binary32为1/8/23位；阶码全0对应零或非规格化数，全1对应无穷或NaN。普通数用偏置127和隐含前导1。

  3. 2.3.3 C语言中的浮点数类型

    float、double的精度和范围需按目标实现核对；字面量、类型转换与舍入会改变中间结果，不能把十进制小数当作必能精确存储。

做题步骤 / 表述模板

拆位型先看阶码：全0再区分零与非规格化数；全1再区分无穷与NaN；其余按(−1)^符号×(1.尾数)×2^(阶码−127)求值。讨论舍入时先求该数量级相邻可表示数的间距，随后按题设舍入模式判断。

别混淆：不要把所有阶码全0位型当零，也不要认为打印成0.1就证明内存恰好存了1/10。NaN不应按普通大小关系比较。

有效精度24位，1.x的最后一位权值为2⁻²³，间距是2⁻²³。越过2的幂边界后间距会随阶码变化。

2.4

非数值数据的编码表示

一句话记住

先辨字符、码点和字节，再看采用哪套字符集与编码。

这样理解：字符编码像字典编号，UTF-8像把编号打包进信封；二者不是同一层。

位串可以表示逻辑真/假，也可以表示字符。ASCII用编码值表示西文字符；汉字可采用GB 2312、GBK或Unicode等字符集。字符集规定字符与编号的对应关系，UTF-8等编码方式规定编号怎样存成字节；查看乱码要先查双方约定的编码。

补足关键机制 / 算例

ASCII中数字字符“0”是30H，“9”是39H；把“7”转为数值7可在题设ASCII条件下减去30H。GB 2312、GBK、Unicode的覆盖范围与编码规则不同；具体汉字的编码值必须依题设或码表核验。按位操作是非数值位串的另一用法，但不能替代字符编码知识。

按教材三级目录逐项核对（3点）
  1. 2.4.1 逻辑值

    真假逻辑与按位运算不是同一层：逻辑运算关注真值，按位与/或/异或逐位处理编码。题中先判运算对象。

  2. 2.4.2 西文字符

    ASCII把字符映为编码值，例如“0”=30H、“A”=41H；字符数字须转换后才能当整数参与数值运算。

  3. 2.4.3 汉字字符

    汉字字符的编号与字节表示依GB 2312、GBK、Unicode/UTF-8等具体体系；“一个汉字恒占两字节”不成立。

做题步骤 / 表述模板

字符题先判“字符、码点、存储字节”是哪一层，再按指定编码查对应值；ASCII大写A是41H，小写a是61H，二者差20H。逻辑题先区分按位与、或、异或和逻辑真假；按位掩码可清零、置位或测试指定位置。

别混淆：不能说“一个汉字恒占两个字节”：所占字节数依编码方式而变；UTF-8也不等于Unicode字符集本身。端序主要涉及多字节数值或编码单元的排列，不能直接解释所有乱码。

合书自测：ASCII字符A的编码是41H，字符“1”的编码是31H。二者能否直接当数值1和十六进制41H作普通加法？点击看解析

不能。41H和31H是字符编码值，字符“1”不是整数1；必须按题意先做字符到数值的转换。若直接把41H当无符号整数，其数值是65，语义已变。

2.5

数据的长度单位与排列

一句话记住

先拆字节，再沿地址递增方向排列。

这样理解：端序像把四张卡片放进四个抽屉：数值不变，只是低地址先放哪张。

位是最小二进制位置，字节通常8位；字长、地址宽度、总线宽度与某个C类型的大小各回答不同问题。多字节对象从低地址到高地址的排列由端序决定：小端把最低有效字节放低地址，大端反之。

按教材三级目录逐项核对（2点）
  1. 2.5.1 数据的宽度和单位

    位、字节、字长、地址宽度和总线宽度各回答不同问题；KiB按2¹⁰换算，kB通常按10³换算。

  2. 2.5.2 数据的存储和排列顺序

    端序只描述多字节对象的字节排列；小端低地址放低有效字节，大端低地址放高有效字节。先拆字节再排地址。

做题步骤 / 表述模板

端序题先把整数拆成各字节，标出低地址到高地址，再按小端或大端排。存储容量换算先确认题目用十进制k/M/G还是二进制Ki/Mi/Gi；地址线m位可区分2ᵐ个地址单位，但每单位多少位另看题设。

别混淆：端序改变的是多字节表示的字节排列，不会改变单字节里的位序，也不改变整数本身的数学值。

合书自测：32位值12345678H在小端机器从低地址到高地址存什么？点击看解析

按字节拆成12H、34H、56H、78H；小端低地址放最低有效字节，故顺序为78H、56H、34H、12H。

2.6

加法器和算术逻辑部件

一句话记住

和位=A⊕B⊕进位；输出进位=AB∨(A⊕B)进位。

这样理解：全加器每一位只管三个输入：A位、B位、低位进位。

全加器一位要考虑本位的两个输入和来自低位的进位；多位加法器把进位从低位传到高位。ALU负责算术和逻辑操作，标志位保存结果的某些性质，后续条件跳转可读取这些标志。

补足关键机制 / 算例

n位补码减法可由A+~B+1实现；有符号加法OF可看进入符号位的进位与符号位输出进位是否不同。无符号借位在不同ISA的标志定义不同，答题应按题设。

按教材三级目录逐项核对（4点）
  1. 2.6.1 全加器和加法器

    全加器输入A、B和低位进位，和位=A⊕B⊕Cin，进位输出=AB∨(A⊕B)Cin；多位加法器要处理进位传播。

  2. 2.6.2 带标志加法器

    CF对应无符号最高位进位，OF对应有符号范围溢出；结果为零、负数等标志也依固定宽度结果设置。

  3. 2.6.3 补码加减运算器

    减法可用A+~B+1在固定位宽下实现；算完还要分别解释截断位型、CF/OF及题设的借位语义。

  4. 2.6.4 算术逻辑部件

    ALU按控制信号选择算术或逐位逻辑操作，并输出结果和相关标志；不要把ALU等同于整个CPU。

做题步骤 / 表述模板

逐位加法写一张表：位号、A位、B位、输入进位、和位、输出进位。若要减法，可用A＋(~B)＋1在固定位宽下实现；再把低n位结果、CF/OF等分别解释。

别混淆：最高位进位与有符号溢出不是一回事；只写截断结果而不判标志，常会丢分。

合书自测：四位1111＋0001的四位结果和最高位进位是什么？点击看解析

低位1＋1先产生进位，进位逐位向上传；四位结果0000，最高位输出进位1。若保留第五位，无符号和为10000₂。

2.7

定点数乘除运算

一句话记住

先定有/无符号与位宽，再按要求列部分积或逐位试商。

这样理解：乘法是“看乘数位选部分积”；除法是“比较、试减、写商位”。

原码乘法把符号与数值部分分开：乘积符号由两个符号位异或得到，绝对值乘法可按乘数每一位形成移位部分积并相加。补码乘除的处理规则不同，不能把原码步骤不加说明套过去。

补足关键机制 / 算例

无符号二进制长除例：13÷3，13=1101₂，3=11₂；按高位向低位逐位试除，商100₂=4，余1。验算3×4+1=13且0≤余数<3。原码乘除先定结果符号，再对绝对值运算；补码乘法可用符号扩展部分积或Booth类算法，补码除法的商/余数规则须按教材算法和题设，不能把原码逐步过程直接移植。

按教材三级目录逐项核对（7点）
  1. 2.7.1 无符号数乘法运算

    乘数位为1时加对应左移部分积，位为0时不加；完整乘积最多需2n位，截成n位应另查高位。

  2. 2.7.2 原码乘法运算

    乘积符号由符号位异或，数值部分按绝对值逐位累加；过程题须列部分积而非只给乘积。

  3. 2.7.3 补码乘法运算

    负数补码的符号位有负权，直接把位串当无符号数做移位相加会错；按题设采用符号扩展或指定补码乘法算法。

  4. 2.7.4 无符号数除法运算

    从高位向低位试商，逐次比较并减去除数；验算被除数=除数×商+余数，且0≤余数<除数。

  5. 2.7.5 原码除法运算

    先用绝对值求商和余数大小，再按题设给商、余数符号；不能把原码的符号位当普通数值位参与除法。

  6. 2.7.6 补码除法运算

    补码商/余数须按指定算法及取整规则；最小负数除以−1可能超出同宽有符号范围。

  7. 2.7.7 整数的乘除运算

    有符号性、结果位宽、截断和溢出共同决定机器结果；先求数学值，再判断表示范围与机器指令规则。

做题步骤 / 表述模板

做原码乘法：先确定符号→列出乘数二进制位→只对为1的位写被乘数左移所得部分积→求和→按题设字长与溢出规则写结果。除法先明确有无符号、商和余数的表示及截断规则。

别混淆：只给十进制乘积不展示部分积，不足以回答“说明运算过程”的简答题。最小负数除以−1还可能超出同宽补码范围。

11=1011₂，对应第0、1、3位为1，所以部分积是13、26、104；总和143=10001111₂。符号正异或负为负，数学结果−143；若要求机器数，还需题设位宽。

2.8

浮点数运算

一句话记住

加减先对阶；乘除先运算阶与尾数；最后都要规格化、舍入、查异常。

这样理解：浮点加法先把小数点对齐；乘法像科学记数法：指数相加、有效数相乘。

浮点加减必须先把指数对齐，否则尾数的位权不同不能直接相加。随后尾数运算、规格化、舍入，并检查上溢/下溢。乘除则先处理符号和指数，再做尾数乘除并归一化、舍入。

补足关键机制 / 算例

简化二进制例：(1.5×2²)×(1.25×2¹)=(1.875×2³)=15；除法则指数相减、尾数相除。真实IEEE 754运算还需处理零、无穷、NaN、非规格化和舍入；不能只算十进制结果。

按教材三级目录逐项核对（2点）
  1. 2.8.1 浮点数加减运算

    先对阶，再尾数加减、规格化、舍入、查上/下溢；移出的保护位等可能影响舍入。

  2. 2.8.2 浮点数乘除运算

    符号按异或，指数分别相加或相减并处理偏置，尾数相乘或相除；最后规格化、舍入并处理特殊值。

做题步骤 / 表述模板

浮点题按“对阶→运算→规格化→舍入→异常检查”列步骤。对阶通常让较小指数的尾数右移，右移丢掉的位仍可能影响舍入；最终结果取决于格式精度和舍入模式。

别混淆：浮点加法一般不满足精确实数的结合律；不能忽略对阶时被移出的位，也不能把“溢出”只理解为整数溢出。

合书自测：为何binary32中2²⁴＋1在最近取偶舍入下会存成2²⁴？点击看解析

2²⁴附近相邻binary32数间距为2，2²⁴＋1恰居两数中间。最近取偶选有效数末位为偶的2²⁴；此结论依题设舍入模式。

补漏专项练习

以下均为自编练习题，先独立作答，再展开解析。

2.1 自编练习题：8位原码、反码、补码各有几个零？为什么8位补码能表示−128？

查看分步解析

原码和反码各有+0、−0两个位型；补码的零只有00000000。补码10000000代表−128，负数端比正数端多一个数；不要把它误读为原码的−0。

2.2 自编练习题：8位加法80H+FFH得到的低8位、无符号进位CF、有符号溢出OF各是什么？

查看分步解析

128+255=383=17FH，低8位7FH并有第9位进位，CF=1。按补码是−128+(−1)=−129，超出[−128,127]，低8位却表示+127，所以OF=1。CF与OF此例恰好都为1，但判定依据不同。

2.3 自编练习题：binary32位型00000001H（按完整32位数值写）代表什么？

查看分步解析

符号0、阶码全0、尾数字段最低位1，是最小正非规格化数。值=2⁻²³×2⁻¹²⁶=2⁻¹⁴⁹，不是零，也不能使用隐含前导1。

2.3 自编练习题：把binary32位型3F800000H拆成符号、实际指数和有效数，求其数值。

查看分步解析

符号位0；阶码7FH=127，实际指数127−127=0；尾数字段全0且为规格化数，有效数1.0。数值为+1.0×2⁰=1.0。

2.4 自编练习题：已知ASCII，“7”的编码37H。如何得到整数7？为什么不能把37H直接解释为十进制7？

查看分步解析

在ASCII前提下减去字符“0”的编码30H：37H−30H=07H，即整数7。37H若当普通整数是十进制55；字符与数值的语义必须先区分。

2.5 自编练习题：32位整数12345678H在小端机器的连续四个字节，从低地址到高地址依次是什么？

查看分步解析

先按高到低有效位拆出12H、34H、56H、78H；小端低地址放最低有效字节，因此地址递增顺序为78H、56H、34H、12H。

2.6 自编练习题：一位全加器A=1、B=1、输入进位Cin=1，和位与输出进位分别是什么？

查看分步解析

1+1+1=3=11₂，因此和位1、输出进位1。也可用S=A⊕B⊕Cin=1，Cout=AB∨(A⊕B)Cin=1验证。

2.7 自编练习题：按无符号整数求13÷3的商和余数，并验算。

查看分步解析

13=1101₂，3=11₂。最高两位11₂可减去11₂，形成商的4位权；余下再处理01₂，不能再减3，所以商100₂=4、余1。验算3×4+1=13，且余数小于3。

2.7 自编练习题：8位补码表示的−128除以−1，数学商是多少？为何不能直接写回8位补码？

查看分步解析

数学商是+128；8位补码最大为+127，因此商超出范围。只取低8位会得到80H并被解释为−128，不能冒充正确有符号商。具体机器异常或标志按题设ISA。

2.8 自编练习题：在不考虑舍入的简化二进制浮点模型中，(1.5×2²)×(1.25×2¹)是多少？

查看分步解析

3.1

程序转换概述

一句话记住

源代码能重编译，不代表现有二进制能跨ISA直接跑。

这样理解：汇编像机器码的注释版；ISA规定机器听得懂的指令词汇。

高级语言通过编译、汇编等步骤变为机器可执行编码。ISA规定软件能看见的指令、寄存器、数据类型及其行为；汇编是机器指令的人类可读写法，但一条高级语言语句可能对应多条机器指令。

补足关键机制 / 算例

比较指令系统设计风格时，先看指令复杂度与格式、访存方式、寄存器使用和实现代价。典型精简指令设计倾向规则编码与装入/存储式访存，典型复杂指令设计容纳较丰富的指令和寻址方式；这是设计取向，不等于“一条复杂指令必比多条简单指令快”，也不能由ISA风格直接推出具体CPU的CPI。

按教材三级目录逐项核对（4点）
  1. 3.1.1 机器指令及汇编指令

    机器指令是编码的位串，汇编助记符是人可读表示；高级语言一句可能对应多条指令，反汇编不能恢复原始源码。

  2. 3.1.2 指令集体系结构

    ISA规定软件可见的寄存器、指令及行为；同一ISA可以有不同数据通路和cache实现。

  3. 3.1.3 指令系统设计风格

    比较规则/复杂指令风格时看编码、寻址、寄存器和访存方式；不能由风格单独推断程序速度。

  4. 3.1.4 生成机器代码的过程

    汇编器产出目标文件，链接器处理跨模块引用；目标文件有机器码不代表已能独立运行。

做题步骤 / 表述模板

翻译流程题先区分源、汇编、目标文件与可执行文件；兼容性题分别考察ISA、ABI和操作系统格式。反汇编是从机器码推导汇编表示，不等于恢复原始C源码。

别混淆：“源代码可以重新编译”与“已有二进制可直接运行”是两个不同命题。

合书自测：同一段C源码可以在两种ISA上重新编译，是否说明两种ISA可直接执行同一个二进制文件？点击看解析

不说明。源码经不同目标编译器可产生各自的机器码；原二进制依赖目标ISA以及ABI、文件格式和运行环境。

3.2

IA-32指令系统概述

一句话记住

有效地址=基址+变址×比例+位移；再看是否访存。

这样理解：括号像“去这个地址取物”；LEA只算门牌号，MOV内存操作数才进门取值。

读一条机器级指令，先识别操作数来自立即数、寄存器还是内存。有效地址是访问位置；内存操作数的值还需再读该位置。IA-32的寄存器组织、指令格式和寻址方式为后续数据通路、栈和C代码分析打底。

补足关键机制 / 算例

IA-32常见指令由操作码、寻址信息及可选位移/立即数组成，长度可变。指令写法要先说明所用汇编语法：AT&T语法常写源在前、目的在后；Intel语法次序相反，不能只凭逗号两侧位置判断数据流。

按教材三级目录逐项核对（3点）
  1. 3.2.1 数据类型及其格式

    指令操作数有不同宽度；按题设分清字节、字、双字及符号解释，同一寄存器低位写入对高位影响要看操作宽度。

  2. 3.2.2 寄存器组织和寻址方式

    立即数、寄存器、内存操作数来源不同；常见有效地址=基址+变址×比例+位移，地址不是地址处的数据。

  3. 3.2.3 机器指令格式

    IA-32指令长度可变，由操作码和可选寻址、位移、立即数字段构成；字段位置与编码以具体指令手册为准。

做题步骤 / 表述模板

复杂寻址可按“基址＋变址×比例＋位移”计算。先统一十六进制/十进制单位，再算有效地址；之后看指令究竟是LEA算地址、MOV读值，还是写回内存。

别混淆：括号内的地址表达式本身不是“地址处的内容”。不看指令语义就把LEA和MOV当同一操作，会系统性出错。

合书自测：EAX=100H、ECX=3，8(%eax,%ecx,4)的有效地址是多少？点击看解析

100H＋3×4＋8H＝114H。3×4是十进制12，也就是0CH；100H＋0CH＋08H＝114H。

3.3

IA-32常用指令类型及其操作

一句话记住

追踪最近一次改标志的指令，再选有符号或无符号条件。

这样理解：CMP像只做减法并贴一张状态标签；跳转读标签决定走哪条路。

传送、算术、按位、控制转移是四类常见机器动作。CMP/TEST更新条件码供后续分支使用；条件码的含义又取决于有符号还是无符号解释。CALL/RET改变控制流并与栈上的返回地址配合。

按教材三级目录逐项核对（4点）
  1. 3.3.1 传送指令

    MOV传值，LEA算有效地址；访存传送要辨操作数宽度及源/目的，不能把LEA视为读内存。

  2. 3.3.2 定点算术运算指令

    ADD/SUB等更新结果与条件码；CMP只更新比较相关标志而不保存减法结果。

  3. 3.3.3 按位运算指令

    AND清位、OR置位、XOR翻位；TEST只按位与并设置标志，不回写结果。

  4. 3.3.4 程序执行流控制指令

    条件跳转读标志，CALL保存返回位置并转入过程，RET取回返回位置；有符号与无符号比较选不同跳转条件。

做题步骤 / 表述模板

跟踪题逐条记录“读哪个寄存器/内存→写哪个位置→哪些标志改变→下一条去哪”。读条件跳转前，先查最后一条会改标志的指令；再看有符号条件还是无符号条件。

别混淆：有符号JL与无符号JB不能换用；CMP之后若插入会改标志的算术指令，分支看到的可能不是原比较结果。

合书自测：8位位型80H与01H比较：有符号和无符号哪个更小？点击看解析

按8位补码，80H=−128，小于01H=1；按无符号，80H=128，大于1。位型相同而解释不同，故条件跳转必须匹配解释方式。

3.4

C语言程序的机器级表示

一句话记住

画基本块箭头，再追栈与参数；优化后形式可以不同。

这样理解：if像岔路口，循环像回到岔路口，函数调用像留下返回地址后去办事。

过程调用要传参、保存必要状态、跳转、返回。条件语句在机器级常变成比较与分支；循环可拆为初始化、条件、循环体、更新和回边。栈帧只是常见组织形式，优化编译器可以省略帧指针。

补足关键机制 / 算例

例：if(x==0) y=1; else y=2 可表示为“比较x与0→按条件跳到其中一支→另一支末尾跳过后支→汇合”。while先判断再可能进入循环体，do-while先执行一次再判断；单凭一个后向跳转无法还原原始C语法。

按教材三级目录逐项核对（3点）
  1. 3.4.1 过程调用的机器级表示

    调用约定决定参数、返回值、保存寄存器与栈的责任；CALL/RET是控制转移，不能假定所有函数都有固定栈帧。

  2. 3.4.2 选择语句的机器级表示

    if/switch会形成比较、条件分支与汇合；优化编译也可能用条件传送或跳转表。先画控制流再猜源程序。

  3. 3.4.3 循环结构的机器级表示

    循环可拆成初始化、条件测试、循环体、更新与回边；先验入口测试还是末尾测试，再判是否至少执行一次。

做题步骤 / 表述模板

还原汇编先画基本块和箭头，再分别检查循环第一次是否执行、何时退出。跟栈题先写栈增长方向、当前SP、每次push/pop的宽度，以及CALL保存的返回地址。ABI要由题设指定。

别混淆：不能假定每个函数都有push EBP/mov EBP,ESP，也不能把源语言的一个语句机械对应一条指令。

合书自测：为何只看到一个向后跳转还不足以断言源代码一定是while循环？点击看解析

向后跳转只说明有回边；还需识别入口处是否先测试条件、出口在哪里、是否执行至少一次，以及编译优化。for、while、do-while甚至手写goto都可能形成回边。

3.5

复杂数据类型的分配和访问

一句话记住

数组乘行宽；结构体逐成员对齐并补尾；联合体取最大成员并满足对齐。

这样理解：数组像整齐货架，结构体像不同尺寸物品排队，联合体像多人共用同一格。

真正的二维数组按行连续，地址偏移要乘一整行的元素数；指针数组先取出指针，再访问其指向区域。结构体成员按声明顺序放置但可能插入对齐填充，整体末尾还可能补齐以便数组中每个对象对齐。联合体成员共享起始存储区。

补足关键机制 / 算例

联合体各成员从偏移0开始，大小至少容纳最大成员，还可能按最大对齐要求向上补齐。结构体成员按声明顺序布置，但对齐填充使相邻成员不一定紧挨；求sizeof必须使用题设ABI。

按教材三级目录逐项核对（4点）
  1. 3.5.1 数组的分配和访问

    二维数组按行连续时a[i][j]的元素偏移=i×列数+j；总字节偏移还需乘元素大小。

  2. 3.5.2 结构体数据的分配和访问

    成员按声明顺序但可能插入填充；逐成员向上对齐，末尾按整体对齐补齐，具体大小依ABI。

  3. 3.5.3 联合体数据的分配和访问

    成员共享起始地址；联合体大小至少容纳最大成员，并按最大对齐要求补齐。

  4. 3.5.4 数据的对齐方式

    对齐要求影响成员偏移、对象大小和数组步长；不要把成员大小直接相加当作sizeof。

做题步骤 / 表述模板

数组a[i][j]元素偏移＝i×列数＋j，再乘元素字节数。结构体sizeof题按“每成员向上对齐→放置→最后按整体最大对齐补尾部”列偏移表；必须以题设ABI给的大小/对齐为准。

别混淆：不要把int a[3][4]与int *p[3]当作同一布局；也不要把成员大小直接相加当作结构体sizeof。

合书自测：char对齐1、int对齐4、short对齐2时，struct {char a; int b; short c;}的大小是多少？点击看解析

a偏移0，b为满足4字节对齐放在偏移4，c放在偏移8；成员用到偏移9，整体按4字节对齐补到12。答案依题设的大小和对齐条件。

3.6

兼容IA-32的64位系统

一句话记住

平台ABI先行，再看参数寄存器、栈、类型大小。

这样理解：64位是寄存器/地址体系的一组扩展，不是所有C类型集体翻倍。

x86-64延续许多IA-32概念，但寄存器更宽、可见寄存器更多，寻址与过程调用规则也有扩展。写EAX一般清零RAX高32位，写AX只改低16位；参数怎么传、哪些寄存器由谁保存，则由具体ABI决定。

按教材三级目录逐项核对（3点）
  1. 3.6.1 x86-64的基本特点

    通用寄存器扩展到64位且数量增加；写32位子寄存器通常清零对应64位寄存器高32位。

  2. 3.6.2 x86-64的过程调用

    参数寄存器、栈对齐、保存寄存器由ABI决定；System V AMD64和Windows x64不能混用。

  3. 3.6.3 x86-64的基本指令和对齐

    64位并不让int、long、指针都自动变成同一宽度；指令操作数和对象对齐按平台ABI与题设。

做题步骤 / 表述模板

遇64位迁移题先写明平台ABI，再逐项核对指针、long、int的大小与对齐、参数位置和格式说明符；不要从“64位”三个字推出所有类型都翻倍。涉及寄存器部分写操作时按指令宽度画位段。

别混淆：“x86-64第一个参数一定在RDI”不是跨平台定律；System V AMD64与Windows x64调用约定不同。

合书自测：写EAX与写AX对RAX高位的影响相同吗？点击看解析

不同。通常写EAX会把RAX高32位清零；写AX只更新低16位，其余位保持。具体题目仍须看指令语义。

3.1 自编练习题：某ISA采用规则的装入/存储式访存，能否仅凭这一点断定运行某程序时一定比另一ISA更快？

3.2 自编练习题：EAX=100H、ECX=3，8(%eax,%ecx,4)的有效地址是多少？LEA取得的是地址还是该处数据？

查看分步解析

有效地址=100H+3×4+8H=114H。LEA计算并取得114H这个地址；带内存操作数的MOV才会按指令语义读取该地址处的数据。

3.3 自编练习题：AL=F0H、CL=02H，分别执行8位一操作数mulb与imulb，AX结果及各自CF/OF是什么？

查看分步解析

mulb按无符号算240×2=480=01E0H，AX=01E0H；AH非零，CF=OF=1。imulb按补码算−16×2=−32，AX=FFE0H；高字节FFH是低字节E0H的符号扩展，结果可由8位表示，CF=OF=0。题设若还问EAX高16位，按该指令语义保持不变。

3.4 自编练习题：某循环在入口先检测条件，为假直接跳到出口；另一个循环先执行体、末尾再检测。哪个保证至少执行一次？

查看分步解析

后者保证循环体至少执行一次，对应do-while一类末尾测试；前者可能一次也不执行。编译优化可改变具体跳转形态，判断要基于控制流而非某一个助记符。

3.5 自编练习题：若char大小/对齐均为1，int大小/对齐均为4，union {char a[3]; int b;} 的大小和成员起始偏移是多少？

查看分步解析

联合体成员都从偏移0开始；最大成员占4字节，整体对齐4，故大小4字节。不要把两个成员的大小相加。

3.6 自编练习题：原RAX=FFFF0000ABCDEF12H，写入EAX=12345678H后RAX为何值？若只写AX则能否得到同一值？

查看分步解析

在x86-64中写EAX会清零RAX高32位，故RAX=0000000012345678H。只写AX仅改低16位，其余位保留，不能得到同一值。

可执行文件的生成与加载执行

链接、加载、运行分三层

先用一句话理解

编译后的目标文件仍可能有“地址和名字没定下来”的地方；链接器解析符号并重定位。操作系统加载可执行文件形成进程，CPU才逐条执行指令。

记忆钩子

三段接力：链接定名字和地址；加载建立进程映像；执行按指令更新状态。异常/中断是正常控制流之外的转向。

本章怎么学

跟着算一遍 / 想一遍

例：8位PC相对位移以下一条地址2000H为基准，目标1FD0H。位移=−30H=−48，8位补码字段D0H；先验算−48在[−128,127]范围内。

容易混淆

  • “链接”和“加载”不是同一步：前者处理符号/地址，后者建立运行映像。
  • fork复制的是进程执行上下文；不能说会自动重新执行父进程之前的所有代码。

合上书自测

  1. 解释文件中的可执行映像与运行中的进程有何不同。
  2. 用两句区分符号解析与重定位，再说出PC相对位移的基准。

4.1

可执行文件生成概述

一句话记住

预处理→编译→汇编→链接，逐步写出产物。

这样理解：链接器像施工队：把多个模块的同名接口接好，填上最终引用位置。

编译、汇编结束后得到的目标文件通常还不能单独运行：其中的外部名字和某些地址尚待链接。链接把多个目标文件与库里的定义组合，产出可执行文件；对静态库与动态库的处理时机、路径和共享方式要按题设区分。

按教材三级目录逐项核对（2点）
  1. 4.1.1 预处理、编译和汇编

    预处理处理宏和包含，编译将源语言转为较低级表示，汇编产生机器码与目标文件；阶段边界以所用工具链为准。

  2. 4.1.2 程序的链接过程

    链接将多个目标模块与库组合，解析跨模块符号并处理地址引用；先判静态还是动态链接。

做题步骤 / 表述模板

看到“哪个阶段”先列产物：源文件→目标文件→可执行文件。若问题涉及跨文件引用，多半要想到链接；若涉及进程创建、地址空间建立，则转向加载。答静态/动态链接题至少说明解析时间、依赖关系和运行时装入影响。

别混淆：不能把“有一个main函数”当作文件已可执行的充分条件；仍需目标格式、符号解析和运行环境。

合书自测：目标文件里已有机器码，为何还可能不能直接运行？点击看解析

它可能含未解析外部符号和需要重定位的地址，且缺少适合加载的完整可执行映像。链接器需要处理这些信息并生成可执行文件。

4.2

目标文件格式

一句话记住

链接看节/符号/重定位；加载看段与内存映像。

这样理解：ELF节像装配时按用途分拣的箱子，段像加载时整车搬运的清单。

目标文件把机器码、已初始化数据、未初始化数据、符号表与重定位信息组织成不同部分。ELF中的节便于链接器处理，装载段面向运行时映射；二者不是同义词。未初始化全局/静态数据常由类似.bss的区域表达，文件中可不逐字节存下所有零值。

按教材三级目录逐项核对（4点）
  1. 4.2.1 ELF目标文件格式

    ELF头指出文件类型及表位置；节偏向链接组织，段偏向装载映射，二者不是一一对应。

  2. 4.2.2 可重定位目标文件格式

    可重定位文件保留符号和重定位记录，供链接器合并；含机器码不等于地址已定。

  3. 4.2.3 可执行目标文件格式

    可执行文件含可供装载的程序头与入口信息；仍可能依赖动态库，不一定“所有代码都在文件里”。

  4. 4.2.4 可执行文件的存储器映像

    磁盘文件大小和进程虚拟映像大小不同；.bss可只记录长度，堆栈还会在运行时存在。

做题步骤 / 表述模板

读目标文件示意题先问它是可重定位文件还是可执行文件，再找节表、符号表与重定位表。区分“磁盘文件大小”“加载后的映像大小”“进程运行峰值内存”：.bss、栈、堆和按需映射都可能使三者不同。

别混淆：不要把节与段画成一一对应，也不要断言所有.bss都占与运行时相同的文件字节。不同格式/链接器细节需按题设。

合书自测：一个大型未初始化数组是否必然让可执行文件按数组大小增加？点击看解析

不必然。典型ELF模型可记录未初始化区的大小和装载要求，由加载时提供零初始化存储；文件占用与内存映像占用可以不同。

4.3

符号解析与重定位

一句话记住

先列定义/引用，再分绝对与PC相对计算。

这样理解：符号解析先找到“人”，重定位再填写“地址”；动态链接还会把部分工作留到运行时。

符号解析回答“名字指向哪个定义”；重定位回答“代码/数据中该填什么地址或位移”。本地静态符号、对外可见定义和未定义引用要分开；静态库搜索、弱/强符号、动态链接都可能受工具链规则影响。

补足关键机制 / 算例

静态链接把所需目标模块组合并处理引用；动态链接让共享库可在加载或运行期间参与解析，实际绑定时机依机制而定。全局强/弱符号冲突规则依具体目标格式和工具链，练题应以题设规则为准，不把一种实现当通则。

按教材三级目录逐项核对（4点）
  1. 4.3.1 符号和符号表

    区分本地定义、对外定义与未定义引用；符号表关联名称、位置和属性，不是源代码的完整变量表。

  2. 4.3.2 符号解析和静态链接

    符号解析给引用寻找合适定义；静态库按链接规则选择目标模块，重复定义处理依工具链和题设。

  3. 4.3.3 重定位过程

    重定位把最终地址或相对位移填进指令/数据字段；PC相对位移常按目标减下一条地址，先查位宽范围。

  4. 4.3.4 动态链接

    共享库的部分解析和重定位可在加载或运行期间完成；区分链接时记录依赖与运行时实际装入。

做题步骤 / 表述模板

符号分类先逐翻译单元列定义与引用，标出static内部链接与extern声明。重定位题先确定绝对地址还是PC相对，再按指定公式计算；PC相对位移常用目标地址减“下一条指令”地址，还要查字段位宽范围。

别混淆：不能把变量声明当成所有情形下的定义；也不能把PC相对位移直接写成目标绝对地址。

合书自测：下一条指令地址2000H，目标1FD0H，8位有符号PC相对字段写多少？点击看解析

位移=1FD0H−2000H=−30H=−48，处于8位有符号范围；按补码写入D0H。若目标超出范围，不能简单截低8位当成有效跳转。

4.4

可执行文件的加载

一句话记住

画进程时间线；fork后父子都从调用后继续，exec成功后进入新映像。

这样理解：磁盘程序像剧本，进程像正在演的剧；fork多一个演员，exec换剧本。

加载让可执行文件中的内容及其运行环境进入进程的虚拟地址空间，形成代码、数据、堆、栈等区域。fork产生新进程，exec系列调用让进程执行新的程序映像；二者作用不同。进程标识、打开文件描述等状态也不能与磁盘可执行文件大小混为一谈。

补足关键机制 / 算例

在POSIX语境下，fork创建子进程；成功的execve用指定程序替换当前进程的程序映像，并不会再创建一个新进程，也不会返回到旧程序的下一句。常见启动序列是父进程fork出子进程，子进程调用execve运行另一程序；不要把这两个系统调用合并成一步。

按教材三级目录逐项核对（4点）
  1. 4.4.1 程序和进程的概念

    程序是可重复运行的代码/数据描述，进程包含当前执行状态与地址空间；一个程序文件可对应多个进程。

  2. 4.4.2 进程的虚拟地址空间

    常用示意含代码、数据、堆、栈与映射区；具体布局和地址不应脱离操作系统/ABI硬背。

  3. 4.4.3 execve函数和main函数

    成功execve替换当前进程映像而不创建新进程，也不返回旧代码；运行库启动代码通常再进入main。

  4. 4.4.4 fork函数和程序的启动加载

    fork创建子进程，父子从调用返回处分支继续；跟踪输出时画进程树，考虑分支、缓冲和调度。

做题步骤 / 表述模板

进程题先画时间线：执行fork前几个进程？fork后每个分支是否继续执行后续fork？exec成功后旧代码是否继续？追踪打开文件描述时区分“进程内fd编号”与共享的打开文件描述。

别混淆：fork的返回值在父子中不同；“一次fork必有两个输出”也不普遍，取决于输出语句在哪个分支以及缓冲和调度。

合书自测：一个进程连续执行两次无条件fork，忽略失败，最终多少进程？点击看解析

第一次由1变2；第二次由现有2个进程各自fork一次，变4。画进程树比背“乘2”更稳妥；有条件分支时应逐支分析。

4.5

程序的执行和中央处理器

一句话记住

理想周期=k+n−1，再加停顿/冲刷；异常先判同步还是异步。

这样理解：流水线像洗衣、晾衣、收衣同时处理不同批次；单件并不一定更快。

CPU执行一条指令需要取指、译码、获取操作数、运算与提交结果等动作，具体可由数据通路和控制信号完成。流水线让不同指令的不同阶段重叠，提高理想吞吐率，但数据相关、分支与结构冲突可引入停顿。异常和中断改变正常控制流，并需保存可恢复的状态。

补足关键机制 / 算例

数据通路由寄存器、ALU、总线/多路选择器和存储接口等组成，控制器按指令给出选择与写使能。外部中断通常异步于当前指令；故障等异常与当前指令相关。响应需保存足够状态、转到处理程序，返回到故障指令或后续位置由事件类型决定。

按教材三级目录逐项核对（5点）
  1. 4.5.1 程序及指令的执行过程

    按PC取指，按操作码译码，读取操作数、执行并更新状态；分支可能改写下一条指令地址。

  2. 4.5.2 CPU的基本功能和组成

    数据通路含寄存器、ALU与连接选择，控制器发控制信号；cache与主存提供指令/数据，整体CPU不等于单个ALU。

  3. 4.5.3 打断程序正常执行的事件

    同步异常由当前指令触发，外部中断通常异步；先判来源和是否可恢复，再讨论返回位置。

  4. 4.5.4 异常和中断的响应过程

    保存必要上下文、定位处理入口、处理事件、按规则返回或终止；不同事件的返回PC不一定相同。

  5. 4.5.5 指令流水线的基本概念

    理想k级流水线完成n条指令需k+n−1周期；数据、控制、结构相关会造成停顿或冲刷。

做题步骤 / 表述模板

流水线基础题先写理想k级执行n条指令的周期k+n−1，再按题设加停顿或冲刷周期。异常题先判事件类型与触发时机，说明保存现场、转服务入口、处理、可能返回的位置；返回点不能一概规定为下一条。

别混淆：流水线提高吞吐率不代表单条指令延迟必缩成一个周期。中断是外部事件响应，不能与所有同步异常混为一类。

合书自测：理想5级流水线执行10条指令且无停顿，共需多少周期？点击看解析

首条经过5级需5周期，此后每周期完成一条，余下9条再需9周期，所以5＋10−1＝14周期。若题目有停顿或冲刷，应另加。

4.2 自编练习题：ELF可执行文件中有未初始化的1MiB全局数组，磁盘文件是否必然增加1MiB？

查看分步解析

不必然。典型.bss只记录运行时所需零初始化空间与大小，文件可不逐字节存下所有零；进程映像仍需相应虚拟空间。

4.3 自编练习题：某C文件定义static int x，并用extern声明另一个文件定义的int y。链接视角下二者有什么不同？

查看分步解析

文件作用域static x具有内部链接，在此翻译单元内使用；extern y在此处是对外部定义的引用，需由链接等机制解析。具体符号表记录会受编译优化影响，不能把自动局部变量也直接列作外部符号。

4.4 自编练习题：一个进程fork一次，子进程随后成功execve运行另一程序。此时有几个进程？子进程会返回旧程序中execve的下一句吗？

查看分步解析

忽略失败且没有其他创建操作时共有父、子两个进程。fork创建子进程；成功execve替换子进程映像，不再创建进程，也不返回旧程序中的下一句。

4.5 自编练习题：理想4级流水线执行8条指令，若另有2个停顿周期，共需多少周期？

查看分步解析

理想周期=4+8−1=11；再加2个停顿周期，共13周期。单条延迟和多条总吞吐不能混为一谈。

4.5 自编练习题：缺页故障与外部设备完成中断，哪个通常与当前执行指令同步相关？处理后返回位置能否一概写成下一条？

查看分步解析

缺页故障通常由当前访存指令触发，属于同步异常；设备完成中断通常异步。处理后的继续位置依事件类型和系统处理方式，缺页处理成功后可能重试故障指令，不能统一写成下一条。

从地址一路追到数据

先用一句话理解

CPU要的数据可能在寄存器、cache、主存或辅存。cache利用局部性减少平均访问时间；虚拟存储把程序看到的地址映射到物理位置并提供保护。

  • LRU要按访问序列实时更新，不能用先进先出代替。
  • 写回次数必须说明序列结束是否冲刷脏块。

5.1

存储器概述

一句话记住

时间局部性看再访问，空间局部性看附近地址。

这样理解：存储层次像桌面、抽屉、仓库：越近取用越快，通常越小越贵。

存储层次在速度、容量、成本间取舍：离CPU近的层级通常更快但更小。局部性解释cache为何有效：时间局部性指近期用过的数据可能再用，空间局部性指相邻地址可能很快用到。不能只看某一层的峰值速度判断整个程序。

按教材三级目录逐项核对（4点）
  1. 5.1.1 存储器的分类

    按易失性、介质、速度和位置分类；寄存器、cache、主存、辅存服务不同容量/延迟目标。

  2. 5.1.2 主存储器的组成和基本操作

    存储单元由地址选中，读写通过地址、数据与控制信号配合；地址数与每地址位宽相乘才是位容量。

  3. 5.1.3 存储器的层次化结构

    越靠近CPU通常越快越小；数据按块在层次间搬运，平均访问时间依命中率和缺失代价。

  4. 5.1.4 程序访问的局部性

    时间局部性看重复访问，空间局部性看附近地址；顺序访问仍会有首次装块的冷缺失。

做题步骤 / 表述模板

分析访问模式先写地址序列，再按块大小计算落在哪些块。二维数组按行访问通常更连续，但结论仍要结合元素宽度、cache块大小和初始状态；跨层平均访问时间要写清命中时间与缺失代价口径。

别混淆：“顺序遍历必然全命中”不成立，冷启动首访块仍可能缺失；局部性好也不等于访问次数变少。

合书自测：顺序读一个未装入cache的64B块中的16个4B整数，若块被第一次访问装入，可能发生几次冷缺失？点击看解析

在该简化模型且无干扰下，第一个整数所在块首访1次缺失，其余15次命中。若跨块、初始已缓存或有冲突，须重新模拟。

5.2

主存与CPU的连接及读/写操作

一句话记住

片数=(目标位宽/芯片位宽)×(目标字数/芯片字数)。

这样理解：扩位宽是多片并排组成一个字，扩深度是增加可选的字组。

主存芯片既有“每个地址存多少位”的字长，也有“共有多少个地址”的深度。组成目标主存时可并联芯片扩位宽，再分组扩地址容量。CPU发出地址与读写控制信号，数据经数据线往返；装入/存储指令分别把内存送往寄存器或反向。

补足关键机制 / 算例

SRAM用锁存状态保持数据，通常不需周期性刷新；DRAM以电容电荷保存信息，需要刷新。二者均属易失性存储。芯片连接题若目标位宽或字数不是单片的整数倍，应按实际芯片数量向上取整，再检查地址译码和未用容量，而不能直接把小数片数当答案。

按教材三级目录逐项核对（3点）
  1. 5.2.1 主存芯片技术

    SRAM通常不需周期刷新，DRAM需要刷新；两者都属易失性，不能把“不刷新”误认为断电保存。

  2. 5.2.2 主存与CPU的连接

    按片位宽并联扩位，按地址深度分组扩容；片选/地址译码决定访问哪一组。结果片数必须为整数。

  3. 5.2.3 装入/存储指令的操作过程

    load由内存到寄存器，store由寄存器到内存；实际访存仍可能经过地址转换与cache。

做题步骤 / 表述模板

芯片组合三步：并联片数＝目标字长/芯片位宽；组选数＝目标地址数/芯片地址数；总片数＝两者相乘。之后核对片内地址线与组选信号，不能把“1M×16位”误读成1MB。

别混淆：容量单位位/字节差8倍；按位扩展与按字扩展解决不同维度，单独乘错一个维度都会错。

合书自测：用256K×8位芯片组成1M×16位，需多少片？点击看解析

位宽16/8=2片并联；深度1M/256K=4组；共2×4=8片。这里K与M按同一二进制倍数约定。

5.3

硬盘存储器

一句话记住

寻道+旋转等待+传送，半圈只是均匀随机假设下的均值。

这样理解：磁盘找数据要先移动磁头、再等盘片转到、最后传数据；SSD没有机械等待。

磁盘访问通常分为寻道、等待目标扇区转到磁头下的旋转延迟、数据传送。转速rpm表示每分钟转数，一整圈时间为60/rpm秒；若题设假定随机扇区且均匀分布，平均旋转延迟约半圈。闪存/SSD列在本教材的带星号扩展小节，不能直接套磁盘机械旋转模型。

补足关键机制 / 算例

机械盘若每磁道有N个等长扇区、每圈60/rpm秒，则连续传一个扇区的理想时间约(60/rpm)/N秒，还需按题设考虑控制器/排队开销。磁盘通过控制器和接口与主机交换命令与数据；接口传输速率不是寻道和旋转延迟，分析总时间要分开。出版社目录将闪存和SSD标星号，具体考核要求仍待大纲正文确认，不能据星号自行判定免考或只考概念。

按教材三级目录逐项核对（5点）
  1. 5.3.1 磁盘存储器的结构

    盘片、磁道、扇区和磁头共同定位数据；逻辑块地址与实际物理位置由设备控制机制联系。

  2. 5.3.2 磁盘存储器的性能指标

    简化访问时间=寻道+旋转等待+传送；7200rpm一圈约8.33ms，随机均匀假设下平均半圈约4.17ms。

  3. 5.3.3 磁盘存储器的连接

    主机经控制器/接口发命令与传数据；接口速率不等于机械盘寻道或旋转延迟。

  4. *5.3.4 闪速存储器和U盘

    闪存按电子存储单元工作，无机械旋转；擦写粒度和寿命管理与磁盘模型不同。星号考核深度待大纲正文确认。

  5. *5.3.5 固态硬盘

    SSD由闪存、控制器等组成；无机械寻道但仍有读写、控制与接口开销。不能把磁盘半圈公式套入SSD。

做题步骤 / 表述模板

遇磁盘时间题先读清是否给平均寻道、平均旋转还是某个指定扇区的实际等待。统一ms与s，再按题设加传送时间；多请求是否可重叠、是否有缓存命中须明确。

别混淆：平均半圈只在均匀随机位置等简化假设下使用；不是每次访问都恰好半圈。

合书自测：7200rpm的盘一圈和平均半圈分别约多少毫秒？点击看解析

一圈60/7200秒≈8.333毫秒，半圈≈4.167毫秒。若还要求总访问时间，需另加寻道和传送时间。

5.4

高速缓冲存储器

一句话记住

地址拆成标记|组索引|块内偏移；状态题逐次更新替换顺序与脏位。

这样理解：cache组像停车场：索引找车区，标记验车牌，偏移找车内座位。

cache用主存块/缓存行作为数据搬运单位。直接映射每个块只能到固定一行；组相联先定位组，再在组内多路比较标记。命中/缺失、替换（如LRU）和写策略（写直达、写回、写分配等）共同决定访问结果。

补足关键机制 / 算例

写直达：每次写命中同时更新下层；写回：先改cache并置脏，替换脏行时写下层。写缺失还要单独定写分配或不写分配。若命中时间h、缺失率m、额外缺失代价p，平均访问时间AMAT=h+m×p；必须确认p是否已经包含h。例h=1ns、m=5%、p=40ns，则AMAT=3ns。

按教材三级目录逐项核对（5点）
  1. 5.4.1 cache的基本工作原理

    cache按块/行缓存主存数据，利用局部性降低平均时间；首次访问某块仍可能缺失。

  2. 5.4.2 cache行和主存块之间的映射方式

    直接映射固定一行，全相联可进任意行，组相联固定组内选路；组数=行数/路数。

  3. 5.4.3 cache中主存块的替换算法

    只在候选位置都占满时决定替换；LRU按最近访问更新，FIFO按装入先后更新。

  4. 5.4.4 cache的写策略

    写直达每次写同时更新下层，写回在脏行替换时更新下层；写缺失还需指定写分配与否。

  5. 5.4.5 cache和程序性能

    简化AMAT=命中时间+缺失率×额外缺失代价；先查代价是否已经包含命中时间，避免重复加。

做题步骤 / 表述模板

组相联题固定六步：①明确容量是否只计数据；②行数＝数据容量/块大小；③组数＝行数/路数；④块内偏移位＝log₂块字节数，组索引位＝log₂组数，标记位＝地址位数−前两者；⑤按访问序列逐步更新组状态；⑥写回次数说明结束冲刷口径。

别混淆：cache数据区容量不含标记/有效位时才能直接用容量÷块大小得行数；LRU与FIFO不同，写回脏块不应漏计或重复计。

合书自测：32KiB数据区、64B块、4路、32位字节地址，组数与三段位数？点击看解析

行数32768/64=512，组数512/4=128；偏移log₂64=6位，索引log₂128=7位，标记32−6−7=19位。

5.5

虚拟存储器

一句话记住

虚页号查页框号、页内偏移不变；先判权限/驻留，再拼物理地址。

这样理解：页表像地址翻译字典，TLB像随手便签；查不到便签不等于字典没词条。

进程看到的虚拟地址要经页表等机制映射到物理地址。页内偏移在转换中通常保持不变，虚页号用于寻找页框号；TLB缓存近期地址转换。地址是否合法、访问权限是否允许、页是否驻留是不同判断，缺页并不等于非法访问。

补足关键机制 / 算例

简化串行模型：TLB命中耗t_TLB+t_M，未命中且页驻留耗t_TLB+t_P+t_M；命中率r时平均访问时间=r(t_TLB+t_M)+(1−r)(t_TLB+t_P+t_M)。这里t_P为页表查询时间，缺页与多级页表另计。例t_TLB=1ns、t_P=100ns、t_M=100ns、r=0.9，平均=1+100+0.1×100=111ns。题目若允许TLB与cache并行，不能套此串行式。

按教材三级目录逐项核对（4点）
  1. 5.5.1 虚拟存储器的基本概念

    进程使用虚拟地址，系统映射到物理页框；抽象带来空间管理、共享与保护。

  2. 5.5.2 虚拟地址空间

    页大小2ᵖ字节时低p位为页内偏移，高位为虚页号；页内偏移在页式转换中保持。

  3. 5.5.3 虚拟存储器的实现

    页表存映射与状态，TLB缓存近期转换；TLB未命中不等于缺页，页表可以仍显示页驻留。

  4. 5.5.4 存储保护

    权限位限制读写执行；页存在却无权限与页不在内存的故障原因不同，先查地址有效性和访问类型。

做题步骤 / 表述模板

地址题先由页大小求偏移位数，再分虚页号与页内偏移；检查页表/权限/存在位后替换成物理页框号并拼回偏移。TLB题先判命中，未命中再查页表；若页不在主存，考虑缺页处理。

别混淆：TLB未命中不是缺页：页表可能仍说明页驻留；缺页也不必然意味着程序错误，非法地址/权限违规才要另外处理。

合书自测：4KiB页、虚地址12345H的页内偏移是多少？点击看解析

4KiB=2¹²字节，所以低12位是偏移；12345H的低三位十六进制为345H。虚页号为12H，具体物理地址还需页表映射。

5.1 自编练习题：冷cache中顺序读取同一64B块内的16个4B整数，假设无其他干扰，共有几次强制缺失？

查看分步解析

第一个整数使该块装入，发生1次冷缺失；其余15个仍在同一块，命中。若起始地址未对齐、跨块或有预取，须另算。

5.2 自编练习题：只考虑位宽，用每片8位的存储芯片组成每字10位的存储器，每组至少并联几片？

查看分步解析

至少向上取整10/8=2片，每组实际可给出16位，其中6位在该目标组织下未使用或另有用途；不能答1.25片。还要按目标字数计算组数。

5.3 自编练习题：机械盘接口带宽提高一倍，是否可断定一次随机读的总访问时间减半？

查看分步解析

不能。随机读总时间通常还包括寻道、旋转等待、传送及控制器等开销。接口更快可能缩短传送部分，却不直接把机械寻道和旋转等待减半；必须按题设各部分重新求和。

5.4 自编练习题：命中时间1ns，缺失率5%，额外缺失代价40ns，平均访问时间是多少？

查看分步解析

AMAT=1+0.05×40=3ns。“额外”表示缺失代价不含已经计入的命中查找时间，不能把1ns重复加。

5.4 自编练习题：一个空的2路cache组按顺序访问块A、B、A、C，采用LRU。装入C时换出谁？

查看分步解析

访问A后组内有A，访问B后有A/B；再访问A会把A更新为最近使用，B成为最久未使用。装入C时换出B。若误按FIFO会换出A。

5.5 自编练习题：简化串行模型下，TLB查询1ns、页表查询100ns、数据内存访问100ns，TLB命中率90%，无缺页。平均访问时间是多少？

查看分步解析

命中=1+100=101ns；未命中=1+100+100=201ns；平均=0.9×101+0.1×201=111ns。TLB未命中不等于缺页。

5.5 自编练习题：某虚页TLB未命中，但页表项显示该页驻留且允许读。是否发生缺页？下一步怎样取数？

查看分步解析

不发生缺页。需由页表得到物理页框号，可更新TLB，再按物理地址访问cache/主存。TLB未命中只说明快速转换缓存中没有记录。

5.6 自编练习题：分析Core i7与Linux存储访问示意图时，TLB命中、cache命中、页面驻留三件事各自回答什么问题？能否仅由TLB未命中推出缺页？

查看分步解析

TLB命中表示快速地址转换记录已找到；cache命中表示所需数据块在相应缓存中；页面驻留表示虚页已映射到内存中的物理页框。三者处在不同层次；TLB未命中后查页表，若页仍驻留且权限允许，就不发生缺页。具体查询并行性与cache层级以教材型号和题设为准。

程序中I/O操作的实现

从函数调用走到设备

先用一句话理解

一次read不等于CPU直接伸手去磁盘取字节：用户函数进入内核，内核和驱动安排控制器工作，完成后返回结果；中断负责通知，DMA可负责搬运。

记忆钩子

四层路径：用户函数 → 内核/文件对象 → 设备驱动 → 控制器/设备。比较I/O方式时分开“谁搬运数据”和“谁通知完成”。

本章怎么学

跟着算一遍 / 想一遍

例：每秒1万次中断，每次服务2微秒，CPU用于中断的时间为0.02秒/秒，即2%。这只是该模型下的CPU占用，不等于I/O端到端延迟。

容易混淆

  • 同步read表示调用者等结果，不表示CPU一直忙轮询。
  • read返回的字节数可能小于请求；返回0需按EOF处理。
  • 全双工双向合计带宽不能直接当单方向带宽。

合上书自测

  1. 不看书说出read从用户到设备的四层路径。
  2. 列出文件系统的至少四项功能，并区分路径与文件描述符。
  3. 解释DMA与中断为何可以同时使用。

6.1

I/O子系统概述

一句话记住

分层画路径，再分别问谁搬运、谁通知。

这样理解：I/O是服务链：用户提出请求，内核安排，驱动发命令，设备完成。

I/O把速度、接口和控制方式差异很大的设备接入计算机系统。软件分层让用户程序不必直接操纵每个设备寄存器，硬件接口和控制器则按设备协议执行命令。一次I/O任务可以同时涉及用户缓冲、内核缓冲、DMA和中断。

做题步骤 / 表述模板

分析一条I/O路径时画四层：用户函数→内核对象/调度→驱动→控制器/设备。每层分别回答它持有什么状态、下发什么命令、怎样知道完成；不要一上来就把read等同成设备每字节的物理传送。

别混淆：“有中断”不说明数据一定由CPU逐字节搬运；“有DMA”也不说明CPU无需配置或处理完成。

合书自测：为什么DMA传送完成后仍可能触发中断？点击看解析

DMA负责批量数据搬运，中断负责向CPU通知完成或错误。两种机制解决不同问题，可配合使用；CPU仍需配置、同步和收尾。

6.2

用户空间I/O软件

一句话记住

读写循环按实际返回字节推进；0与负数单独处理。

这样理解：文件名是地址簿里的名字，fd是这个进程手中的取件号。

用户程序通过系统级read/write或C标准I/O库函数访问文件。路径/文件名定位文件对象，文件描述符是进程已打开对象的句柄；标准I/O还可能在用户空间缓冲。一次read/write成功返回的数量可能小于请求长度，必须按返回值推进。

补足关键机制 / 算例

文件名是目录中的命名入口，打开文件后进程用fd访问，文件当前位置与访问权限等状态需按具体接口理解。fread/fwrite等标准I/O可经用户态缓冲，read/write等系统级接口进入内核；因此“调用已返回”“库缓冲已刷新”“数据已持久化”是不同事件。若read返回正数但少于请求，应处理短读；0在普通文件读取常为EOF，具体设备语义仍看接口。

按教材三级目录逐项核对（4点）
  1. 6.2.1 用户程序中的I/O函数

    用户调用库函数或系统级接口提出读写请求；调用返回不等于数据必已掉电持久化。

  2. 6.2.2 文件的基本概念

    路径是命名入口，fd是进程使用的句柄；文件位置、访问权限、目录等抽象由文件系统管理。

  3. 6.2.3 系统级I/O函数

    read/write按实际返回字节数推进；短读/短写、EOF和错误须分开处理。

  4. 6.2.4 C标准I/O库函数

    stdio可在用户空间缓冲；fflush刷新用户态缓冲，不保证底层已持久化。混用stdio与底层fd操作要处理缓冲与位置一致性。

做题步骤 / 表述模板

读满循环维护“已读/剩余”两个量：正数按实际字节推进；0通常表示EOF；负数按错误及可重试条件处理。文件系统功能简答题至少从命名目录、数据存取、空间管理、访问控制与共享几方面作答，再说明接口提供的抽象。

别混淆：stdio刷新只把用户态缓冲交给下一层，不必然等于掉电持久化。fd数字可被关闭后复用，不能当文件永久身份。

合书自测：要读100B，第一次读到40B，第二次read返回0，应怎样处理？点击看解析

累计40B，尚缺60B；0表示到达EOF，应结束循环并向上层报告未读满，不能不改状态地无限重试。

6.3

内核空间I/O软件

一句话记住

列出请求发起、等待方式、完成通知、收尾开销。

这样理解：设备无关层定通用规矩，驱动懂设备方言，中断处理像设备回电。

设备无关层提供统一对象、缓冲与权限等共同服务；驱动知道具体设备寄存器与命令；中断服务程序响应设备事件并完成必要的快速处理。分层的目的不是每台设备都严格经过相同长度的调用链，而是把通用工作和设备特有工作分开。

按教材三级目录逐项核对（3点）
  1. 6.3.1 设备无关I/O软件层

    把命名、权限、缓冲等通用功能与设备特有操作分开；不是每个设备都走完全相同调用路径。

  2. 6.3.2 设备驱动程序

    驱动把通用请求转成设备控制器可理解的寄存器操作或命令，并管理具体设备状态。

  3. 6.3.3 中断服务程序

    设备通知到来后需保存/处理必要状态并唤醒后续工作；中断服务本身也消耗CPU时间。

做题步骤 / 表述模板

遇驱动/中断题先写设备请求何时发起、CPU何时可以做别的事、事件到来后谁处理。若要求计算CPU占用，频率×每次服务时间得到每秒CPU时间；再除1秒换百分比，并注明是否计设置、复制和调度开销。

别混淆：中断减少持续轮询，但每次进入/退出和服务仍要CPU时间。中断处理程序通常不宜执行可阻塞的长任务。

合书自测：每秒10000次中断，每次服务2微秒，服务占1秒CPU时间的多少？点击看解析

10000×2微秒=20000微秒=0.02秒，占2%。这是题设仅计服务程序时间的结果，其他开销若给出应另加。

6.4

I/O硬件与软件的接口

一句话记住

分开比较CPU轮询、数据搬运者、完成通知者。

这样理解：查询像不停打电话，中断像等对方回电，DMA像请搬运工搬整箱。

总线让CPU、内存与I/O接口交换命令、地址和数据。设备控制器有状态、控制和数据寄存器，端口可独立编址或内存映射。查询式传送由CPU反复检查状态；中断驱动改用通知；DMA控制器可批量传数据。接口速率还要区分单向/双向、位/字节与协议有效载荷。

补足关键机制 / 算例

独立编址I/O有单独端口地址空间和相应指令；内存映射I/O把设备寄存器编入地址空间，能用适用的访存操作访问，但寄存器可能有读清/写1清等副作用。中断向量用于定位处理入口，优先级与屏蔽决定多个请求如何处理；具体规则按题设。

按教材三级目录逐项核对（5点）
  1. 6.4.1 输入/输出设备

    设备可按功能和传输单位分类；速度与数据形式不同，系统需接口和缓冲来适配。

  2. 6.4.2 基于总线的互连结构

    总线传地址、数据和控制信息；带宽题明确频率、每周期传输次数、宽度和有效载荷比例。

  3. 6.4.3 I/O接口的功能和结构

    接口/控制器协调主机与设备，常有状态、控制和数据寄存器；读写寄存器可能有副作用。

  4. 6.4.4 I/O端口及其编址

    独立编址用单独I/O地址空间，内存映射I/O占用地址空间；两者访问指令和地址解释不同。

  5. 6.4.5 中断系统

    中断请求、屏蔽/优先级、向量入口及返回形成响应过程；DMA搬运与中断通知可以并用。

做题步骤 / 表述模板

带宽题逐项写：频率×每周期传输次数×每次字节数×通道数，再乘有效载荷比例；最后确认十进制GB/s还是二进制GiB/s。控制方式题把“CPU是否轮询”“数据由谁搬运”“完成怎样通知”三列分别比较。

别混淆：“总线频率×位宽”只在单次/周期、无额外开销等特定条件下成立；读清/写1清状态寄存器不能当普通RAM反复读写。

合书自测：200MHz、每周期2次传送、每次8B，单向原始带宽是多少？点击看解析

200×10⁶×2×8=3.2×10⁹B/s，即十进制3.2GB/s。若题目给协议开销，还要折算有效载荷。

6.1 自编练习题：一次DMA读盘完成后触发中断，这是否重复做了同一件事？

查看分步解析

不重复。DMA负责批量数据搬运，中断负责通知CPU操作完成或出错；CPU仍要配置DMA并在完成后处理状态。

6.2 自编练习题：读100B时，read先返回40，第二次返回0，程序应记录多少已读字节？

查看分步解析

累计40B；普通文件的0表示EOF，应停止并报告尚缺60B，不能保持剩余量不变而无限循环。

6.3 自编练习题：统一文件接口、设置设备寄存器、响应设备完成事件，通常分别由哪层承担？

查看分步解析

统一接口/共性缓冲权限属于设备无关I/O层；具体设备命令和寄存器由驱动处理；完成事件由中断服务程序及时响应，再交后续代码收尾。具体系统分工可有差异。

6.4 自编练习题：单向总线100MHz、每周期2次传送、每次4B，有效载荷占80%。有效带宽是多少？

查看分步解析

原始带宽=100×10⁶×2×4=800×10⁶B/s；有效带宽乘0.8，得640×10⁶B/s，即十进制640MB/s。注意位与字节、单向与双向口径。

单项选择

圈出题干里的位宽、单位、条件和“错误/正确”。先独立算结论，再看选项；不要凭熟悉词组猜。
